## 2. 训练与评估是两套行为

训练时：

~~~python
model.train()
~~~

评估时：

~~~python
model.eval()
~~~

这个开关主要影响有状态或随机行为的模块：

- Dropout：训练时随机丢弃，评估时关闭
- BatchNorm：训练时使用当前 batch 统计并更新运行统计；评估时使用保存的运行统计

它不会：

- 自动关闭梯度记录
- 自动计算指标
- 自动把数据移到设备

因此评估还需要：

~~~python
with torch.inference_mode():
    ...
~~~

可以记成两条独立轴：

| 控制项 | 作用 |
| --- | --- |
| `model.train()/eval()` | 控制模块行为 |
| `no_grad()/inference_mode()` | 控制是否记录自动微分 |

## 3. Dropout 行为验证

~~~python
import torch
from torch import nn

model = nn.Sequential(
    nn.Linear(4, 8),
    nn.ReLU(),
    nn.Dropout(p=0.5),
    nn.Linear(8, 2),
)
x = torch.ones(16, 4)
~~~

训练模式：

~~~python
model.train()
y1 = model(x)
y2 = model(x)
print(torch.equal(y1, y2))  # 通常 False
~~~

评估模式：

~~~python
model.eval()
with torch.inference_mode():
    y1 = model(x)
    y2 = model(x)
print(torch.equal(y1, y2))  # True
~~~

如果验证指标每次变化，先检查是否忘记 `eval()`。

## 4. 分类评估函数

~~~python
def evaluate(
    model,
    data_loader,
    criterion,
    device,
):
    model.eval()
    total_loss = 0.0
    total_correct = 0
    total_samples = 0

    with torch.inference_mode():
        for inputs, targets in data_loader:
            inputs = inputs.to(device)
            targets = targets.to(device)

            logits = model(inputs)
            loss = criterion(logits, targets)
            predictions = logits.argmax(dim=1)

            batch_size = targets.shape[0]
            total_loss += loss.item() * batch_size
            total_correct += (predictions == targets).sum().item()
            total_samples += batch_size

    if total_samples == 0:
        raise ValueError("评估集不能为空")

    return {
        "loss": total_loss / total_samples,
        "accuracy": total_correct / total_samples,
    }
~~~

为什么使用 `targets.shape[0]`：

- 最后一个 batch 可能较小
- 输出结构以后可能变化
- 标签数最直接表示实际评估样本数

## 5. 保存预测用于错误分析

~~~python
all_predictions = []
all_targets = []

with torch.inference_mode():
    for inputs, targets in data_loader:
        logits = model(inputs.to(device))
        predictions = logits.argmax(dim=1).cpu()
        all_predictions.append(predictions)
        all_targets.append(targets.cpu())

predictions = torch.cat(all_predictions)
targets = torch.cat(all_targets)
~~~

如果数据顺序稳定，还可以一起保存：

- sample ID
- 原始文本或文件路径
- logits 或概率
- 预测类别
- 真实类别

不要只保存错误样本的截图；结构化预测文件才能重复统计。

## 6. 为什么只根据验证集选模型

训练期间每轮可能得到一组不同参数：

~~~text
epoch 1  → val accuracy 0.82
epoch 2  → val accuracy 0.86
epoch 3  → val accuracy 0.84
~~~

选择 epoch 2 是模型选择行为，必须使用验证集。

如果每轮都看测试集并挑测试结果最好的 epoch，测试集已经参与调参，不再是独立最终评估。

正确流程：

1. 使用训练集更新参数。
2. 使用验证集选择超参数、轮次和阈值。
3. 冻结完整方案。
4. 加载最佳验证检查点。
5. 对测试集只运行最终评估。

## 7. 最佳权重与断点续训

### 7.1 最佳推理权重

只为部署或评估时，最小内容是：

~~~python
torch.save(model.state_dict(), "best_model.pt")
~~~

还必须在旁边保存：

- 模型结构配置
- 标签映射
- 输入预处理配置
- 代码或版本信息

否则只有权重通常无法正确重建输入与模型。

### 7.2 断点续训检查点

为了继续训练，至少保存：

~~~python
checkpoint = {
    "model_state": model.state_dict(),
    "optimizer_state": optimizer.state_dict(),
    "epoch": epoch,
    "best_val_metric": best_val_metric,
    "config": config,
}
~~~

如果使用学习率调度器，还要保存：

~~~python
"scheduler_state": scheduler.state_dict()
~~~

追求严格续训时还可保存：

- Python 随机状态
- NumPy 随机状态
- PyTorch CPU 随机状态
- CUDA 随机状态
- DataLoader 采样器或 Generator 状态

## 8. 保存最佳检查点

~~~python
best_val_loss = float("inf")

for epoch in range(epochs):
    train_loss = train_one_epoch(...)
    val_metrics = evaluate(...)

    if val_metrics["loss"] < best_val_loss:
        best_val_loss = val_metrics["loss"]
        checkpoint = {
            "model_state": model.state_dict(),
            "optimizer_state": optimizer.state_dict(),
            "epoch": epoch,
            "best_val_metric": best_val_loss,
            "config": config,
        }
        torch.save(checkpoint, checkpoint_path)
~~~

如果只保存在内存中，`state_dict` 需要深拷贝：

~~~python
from copy import deepcopy

best_state = deepcopy(model.state_dict())
~~~

`torch.save` 会在保存时序列化当前值；内存变量则可能继续引用模型存储。

## 9. 加载权重用于推理

~~~python
device = torch.device("cpu")
model = MyModel(**config["model"])

state = torch.load(
    "best_model.pt",
    map_location=device,
    weights_only=True,
)
model.load_state_dict(state)
model.to(device)
model.eval()
~~~

`map_location` 允许把 GPU 保存的权重加载到 CPU。

加载状态之后要检查 `load_state_dict` 返回结果。默认 `strict=True`，键缺失或多余会报错，这在学习阶段通常是好事。

不建议为了“先跑起来”随意设置 `strict=False`，因为可能留下未加载的随机层。

## 10. 恢复训练

~~~python
checkpoint = torch.load(
    "checkpoint.pt",
    map_location=device,
    weights_only=True,
)

model.load_state_dict(checkpoint["model_state"])
optimizer.load_state_dict(checkpoint["optimizer_state"])

start_epoch = checkpoint["epoch"] + 1
best_val_metric = checkpoint["best_val_metric"]
~~~

恢复顺序：

1. 使用保存配置重新创建模型。
2. 创建兼容优化器。
3. 加载模型状态。
4. 加载优化器状态。
5. 恢复轮次和最佳指标。
6. 继续从 `epoch + 1` 训练。

恢复优化器状态很重要，因为 Momentum 和 AdamW 都有历史缓存。只加载模型权重并不是严格的断点续训。

## 11. 不要保存完整模型对象

不推荐：

~~~python
torch.save(model, "full_model.pt")
~~~

它会把加载过程与 Python 类路径和代码结构强绑定，也扩大不可信反序列化风险。

推荐：

~~~python
torch.save(model.state_dict(), "weights.pt")
~~~

或保存由状态字典和基础配置组成的检查点。

只加载可信来源的检查点。模型文件可能包含序列化数据，不应把未知文件当普通静态数据随意加载。

## 12. 固定随机种子

~~~python
import random
import numpy as np
import torch


def seed_everything(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(seed)
~~~

调用时机：

~~~python
seed_everything(42)
model = MyModel(...)
~~~

如果先创建模型后设置种子，初始化已经发生，来不及影响现有参数。

## 13. 复现并不等于跨环境完全相同

即使固定种子，也可能因以下因素不同：

- PyTorch 版本
- CPU、CUDA、MPS 平台
- 驱动和底层库版本
- 多线程或多 worker 调度
- 某些非确定性算子
- 浮点运算顺序

因此实验记录至少包含：

~~~python
environment = {
    "python": platform.python_version(),
    "torch": torch.__version__,
    "device": str(device),
    "seed": seed,
}
~~~

复现目标通常是：

- 同一环境下结果稳定
- 不同环境下指标在合理误差范围
- 结论不依赖一次幸运随机运行

严格确定性可能降低性能。调试阶段更重视确定性，最终性能实验再权衡。

## 14. 早停

~~~python
best = float("inf")
epochs_without_improvement = 0

for epoch in range(epochs):
    ...
    val_loss = evaluate(...)["loss"]

    if val_loss < best:
        best = val_loss
        epochs_without_improvement = 0
        save_checkpoint(...)
    else:
        epochs_without_improvement += 1

    if epochs_without_improvement >= patience:
        break
~~~

要明确：

- 监控哪个验证指标
- 越大越好还是越小越好
- 最小改善量 `min_delta`
- patience 的单位是 epoch 还是 evaluation 次数

早停是一种模型选择和正则化手段，不是测试集选择工具。

## 15. 评估与检查点测试

建议自动化检查：

1. Dropout 在评估模式下输出稳定。
2. 评估不会产生参数梯度。
3. 评估样本数等于 Dataset 长度。
4. 最后小 batch 被正确加权。
5. 保存与加载后固定输入输出一致。
6. 优化器状态可以恢复。
7. 最佳检查点只在验证指标改善时替换。
8. 新进程只依赖配置和权重即可预测。

## 16. 常见错误

### 16.1 只使用 no_grad，忘记 eval

Dropout 仍随机，BatchNorm 仍使用训练行为。

### 16.2 只使用 eval，忘记 no_grad

输出可能正确，但仍构建计算图，浪费内存和时间。

### 16.3 保存最后模型而不是最佳模型

最后一轮可能已经过拟合。必须按验证指标保存最佳检查点。

### 16.4 只恢复模型，不恢复优化器

推理没问题，但断点续训时会丢失优化器历史。

### 16.5 保存权重但不保存配置

之后不知道 hidden size、类别数、词表或预处理方法。

### 16.6 使用测试集决定何时保存

测试集泄漏。保存条件必须来自验证集。

### 16.7 指标按 batch 简单平均

最后 batch 较小时会产生偏差。

## 17. 自测题

1. `eval()` 和 `inference_mode()` 的职责有什么不同？
2. 为什么保存最佳模型必须依据验证集？
3. 推理权重和断点续训检查点有什么区别？
4. 为什么恢复 AdamW 时需要加载 optimizer state？
5. 为什么只固定随机种子仍不能保证跨平台完全一致？
6. `map_location="cpu"` 有什么作用？
7. 为什么内存中的最佳 `state_dict` 需要深拷贝？

答案：

~~~text
1. eval 控制模块行为；inference_mode 关闭梯度记录。
2. 测试集必须保持独立，训练集用于参数更新。
3. 续训还需要优化器、轮次、最佳指标和配置等状态。
4. AdamW 保存一阶、二阶动量等历史。
5. 算法、库、硬件和浮点执行顺序可能不同。
6. 把检查点 Tensor 映射到 CPU，避免依赖原保存设备。
7. state_dict 中的 Tensor 可能仍引用正在继续更新的模型存储。
~~~
