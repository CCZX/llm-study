## 2. 从手写梯度到自动微分

第一阶段已经手写过：

~~~text
y_hat = X @ w + b
loss = mean((y_hat - y)²)

dL/dw = (2/N) Xᵀ @ (y_hat - y)
dL/db = 2 mean(y_hat - y)
~~~

PyTorch 可以根据前向运算自动构建计算图，并沿图反向应用链式法则：

~~~python
import torch

x = torch.tensor([[1.0], [2.0], [3.0]])
y = torch.tensor([3.0, 5.0, 7.0])

w = torch.tensor([0.0], requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

predictions = x @ w + b
loss = ((predictions - y) ** 2).mean()
loss.backward()

print(w.grad)
print(b.grad)
~~~

自动微分不是数值差分。它会记录每一步局部导数，并精确执行链式法则，只受到正常浮点误差影响。

## 3. requires_grad

~~~python
x = torch.tensor(3.0, requires_grad=True)
y = x**2 + 2 * x + 1
~~~

`requires_grad=True` 表示需要追踪依赖该 Tensor 的运算，以便之后求梯度。

~~~python
print(x.requires_grad)  # True
print(y.requires_grad)  # True
print(y.grad_fn)        # 记录最后一步运算
~~~

通常只有可微的浮点或复数 Tensor 才能需要梯度。类别编号和 Token ID 是整数，不对它们求梯度。

## 4. 叶子 Tensor 与非叶子 Tensor

~~~python
x = torch.tensor(3.0, requires_grad=True)
y = x * 2
z = y**2
~~~

- `x` 是用户直接创建、需要梯度的叶子 Tensor
- `y` 和 `z` 是运算结果，通常是非叶子 Tensor
- 调用 `z.backward()` 后，梯度默认写入叶子 Tensor 的 `x.grad`

~~~python
z.backward()

print(x.grad)  # tensor(24.)
print(y.grad)  # 默认通常是 None
~~~

计算：

~~~text
y = 2x
z = y²
dz/dx = dz/dy × dy/dx = 2y × 2 = 4y
x=3, y=6，因此 dz/dx=24
~~~

如果确实需要查看非叶子 Tensor 的梯度，可以在反向前调用 `retain_grad()`，但日常训练很少需要。

## 5. backward 与标量输出

### 5.1 标量损失

~~~python
x = torch.tensor(3.0, requires_grad=True)
loss = (x - 5) ** 2
loss.backward()

print(x.grad)  # 2 * (3 - 5) = -4
~~~

`loss` 是标量，PyTorch 隐含地从上游梯度 1 开始反向传播。

### 5.2 非标量输出

~~~python
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = x**2
~~~

直接调用 `y.backward()` 会报错，因为 PyTorch 不知道要计算向量输出的哪种组合。

常见做法是先聚合成标量：

~~~python
y.sum().backward()
print(x.grad)  # tensor([2., 4., 6.])
~~~

也可以显式提供上游梯度：

~~~python
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = x**2
y.backward(torch.tensor([1.0, 0.5, 0.0]))
~~~

得到的是向量—雅可比乘积。基础训练中，损失函数通常已经把每个样本的损失聚合成标量。

## 6. 动态计算图

PyTorch 默认使用动态计算图：每次运行前向代码时，根据实际执行的 Python 分支重新构图。

~~~python
def dynamic_function(x: torch.Tensor) -> torch.Tensor:
    if x.item() > 0:
        return x**2
    return x**3
~~~

不同输入可以走不同路径。这让普通 Python 调试器、打印和断点非常实用。

反向传播后，计算图中用于反向的中间缓存通常会被释放：

~~~python
x = torch.tensor(2.0, requires_grad=True)
y = x**2
y.backward()
# y.backward()  # 第二次对同一张图反向通常会报错
~~~

如果确实需要对同一张图反向多次，可以使用 `retain_graph=True`，但训练循环通常应重新执行前向传播，而不是长期保留计算图。

## 7. 梯度默认累积

~~~python
x = torch.tensor(2.0, requires_grad=True)

(x**2).backward()
print(x.grad)  # 4

(3 * x).backward()
print(x.grad)  # 7，而不是 3
~~~

第二次梯度 3 被加到原来的 4 上。

PyTorch 这样设计是为了支持：

- 一个参数被多条路径使用
- 梯度累积，模拟更大的 batch
- 多个损失共同反向

训练时如果不需要累积，就必须在每次更新前清理旧梯度：

~~~python
optimizer.zero_grad(set_to_none=True)
~~~

`set_to_none=True` 让梯度变成 `None`，通常比填零更省操作，也能区分“没有得到梯度”和“梯度恰好为零”。

## 8. 最小手写参数更新

不使用优化器时：

~~~python
w = torch.tensor(0.0, requires_grad=True)

for step in range(100):
    loss = (w - 3.0) ** 2
    loss.backward()

    with torch.no_grad():
        w -= 0.1 * w.grad

    w.grad = None
~~~

为什么更新参数要放在 `no_grad` 中？

如果 PyTorch 记录“参数减去梯度”这一更新操作，更新后的参数不再是简单叶子 Tensor，后续图会不断连接旧步骤，既不符合普通 SGD，也会导致内存和梯度问题。

不要写：

~~~python
w.data -= 0.1 * w.grad
~~~

`.data` 会绕过自动微分的安全检查，可能悄悄产生错误。教学和常规代码优先使用 `torch.no_grad()`。

## 9. detach、no_grad 与 inference_mode

### 9.1 detach

`detach()` 返回一个与原 Tensor 共享存储、但从当前计算图分离的 Tensor：

~~~python
x = torch.tensor(2.0, requires_grad=True)
y = x**2
detached = y.detach()

print(detached.requires_grad)  # False
print(detached.grad_fn)        # None
~~~

常见用途：

- 记录日志时把损失转成 Python 数字
- 截断序列模型的历史计算图
- 把结果转成 NumPy

~~~python
loss_value = loss.detach().cpu().item()
~~~

### 9.2 no_grad

`torch.no_grad()` 在代码块内不记录梯度：

~~~python
with torch.no_grad():
    predictions = model(inputs)
~~~

适合验证、推理和手动参数更新。

### 9.3 inference_mode

`torch.inference_mode()` 比 `no_grad` 更严格，可能进一步减少推理开销：

~~~python
with torch.inference_mode():
    predictions = model(inputs)
~~~

推理结果之后不需要重新参与带梯度计算时，优先考虑它。若需要更灵活地把结果用于后续计算，`no_grad` 更容易理解。

## 10. 自动微分验证解析梯度

~~~python
x = torch.tensor(
    [[1.0, 2.0], [2.0, -1.0], [0.5, 3.0]],
    dtype=torch.float64,
)
y = torch.tensor([2.0, -1.0, 3.0], dtype=torch.float64)
w = torch.tensor([0.2, -0.3], dtype=torch.float64, requires_grad=True)
b = torch.tensor(0.1, dtype=torch.float64, requires_grad=True)

predictions = x @ w + b
loss = ((predictions - y) ** 2).mean()
loss.backward()
~~~

手写公式：

~~~python
errors = predictions.detach() - y
manual_w = (2.0 / len(x)) * (x.T @ errors)
manual_b = 2.0 * errors.mean()

assert torch.allclose(w.grad, manual_w)
assert torch.allclose(b.grad, manual_b)
~~~

这一步把第一阶段的数学与 PyTorch 自动微分连接起来。不要只相信框架；至少做一次形状和数值对照。

## 11. autograd.grad

除了把梯度写入 `.grad`，还可以直接返回梯度：

~~~python
x = torch.tensor(2.0, requires_grad=True)
y = x**3

(grad_x,) = torch.autograd.grad(y, x)
print(grad_x)  # 12
~~~

`torch.autograd.grad` 适合：

- 梯度检查
- 需要高阶梯度的研究代码
- 不希望修改参数 `.grad` 的计算

基础训练仍以 `loss.backward()` 为主。

## 12. 常见错误

### 12.1 误以为梯度会自动清零

现象：损失震荡、更新越来越大。

检查：每个 step 是否在反向前调用 `optimizer.zero_grad(...)`。

### 12.2 在 backward 前调用 item

~~~python
loss = model_loss.item()
loss.backward()  # Python float 没有 backward
~~~

保留 Tensor 做反向，只在记录日志时额外调用 `item()`。

### 12.3 在需要梯度的 Tensor 上原地修改

~~~python
x = torch.tensor(2.0, requires_grad=True)
x += 1  # 可能报叶子 Tensor 原地操作错误
~~~

参数更新应放在 `no_grad` 中，其他地方优先使用非原地表达式。

### 12.4 计算图意外跨 step 保留

常见原因：

- 把 loss Tensor 本身追加到列表，而不是追加 `loss.item()`
- 跨 batch 传递隐藏状态但没有 `detach()`
- 不必要地使用 `retain_graph=True`

### 12.5 参数没有梯度

优先检查：

- `parameter.requires_grad` 是否为 True
- 参数是否真的参与前向
- 中间是否调用了 `detach`、`item` 或 NumPy
- 是否在 `no_grad` 中执行了前向

## 13. 自测题

1. 为什么 `x.grad` 在两次 `backward` 后会相加？
2. 为什么验证时不用 `backward`，但仍要调用 `model.eval()`？
3. `detach()` 与 `clone()` 的目的有什么不同？
4. 为什么损失通常是标量？
5. 为什么不建议使用 `parameter.data` 更新参数？
6. 叶子 Tensor 与非叶子 Tensor 的梯度保存行为有什么不同？

参考答案：

- 梯度默认累积，便于多路径和梯度累积。
- `eval()` 控制 Dropout、BatchNorm 等模块行为；是否记录梯度由 `no_grad` 或 `inference_mode` 控制，两者职责不同。
- `detach` 切断计算图但可能共享存储；`clone` 复制数据但不一定切断计算图。
- 标量损失为反向传播提供明确的单一优化目标。
- `.data` 绕过自动微分安全检查，容易静默破坏梯度正确性。
- 叶子 Tensor 的梯度默认写入 `.grad`；非叶子 Tensor 默认不保留，除非显式 `retain_grad()`。
