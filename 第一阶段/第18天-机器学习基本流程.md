# 第 18 天：机器学习基本流程

## 今日目标

完成本节后，应当能够：

- 正确定义样本、特征、标签、模型、参数和超参数
- 解释训练集、验证集和测试集的不同职责
- 建立简单基线并选择合适的损失与评价指标
- 区分欠拟合、过拟合、优化问题和泛化问题
- 计算准确率、精确率、召回率和混淆矩阵
- 避免预处理、调参和特征选择中的数据泄漏
- 组织一次可复现的机器学习实验

## 1. 端到端流程

一个完整机器学习项目通常包含：

```text
定义问题与指标
    ↓
收集并理解数据
    ↓
划分训练/验证/测试集
    ↓
只用训练集拟合预处理
    ↓
建立简单基线
    ↓
训练候选模型
    ↓
用验证集选择模型和超参数
    ↓
冻结所有决策
    ↓
只在最后使用一次测试集
    ↓
记录结果、局限和复现方法
```

模型训练只是其中一环。数据、指标和评测流程错误时，复杂模型也无法得到可信结论。

## 2. 先定义问题

在写模型前回答：

1. 输入是什么？
2. 输出是什么？
3. 是回归、二分类、多分类还是多标签任务？
4. 哪种错误代价更高？
5. 离线指标达到多少才有实际价值？
6. 推理延迟、内存和成本有什么限制？

例子：

```text
问题：根据葡萄酒理化指标预测质量评分
输入：11 个连续特征
输出：一个质量分数
任务：回归
主要指标：验证集 RMSE
基线：始终预测训练集质量均值
```

## 3. 样本、特征和标签

```text
X 形状：(samples, features)
y 形状：(samples,) 或 (samples, targets)
```

```python
x = np.array([
    [10.2, 0.31, 9.8],
    [11.5, 0.28, 10.4],
])
y = np.array([6.0, 7.0])
```

- 每一行是一个样本。
- 每一列是一个特征。
- `y` 是希望模型预测的标签或目标。

必须确保第 `i` 行特征与第 `i` 个标签属于同一个样本。打乱数据时，应使用同一组索引同时处理 `X` 和 `y`。

## 4. 模型、参数与超参数

线性模型：

```text
y_hat = X @ w + b
```

- 参数：`w`、`b`，训练过程从数据中学习。
- 超参数：学习率、训练轮数、隐藏层大小等，由开发者设定或选择。

| 类型 | 示例 | 如何获得 |
| --- | --- | --- |
| 参数 | 权重、偏置 | 梯度下降学习 |
| 超参数 | 学习率、层数、正则强度 | 根据验证集选择 |

测试集不能用来选择超参数，否则它已经参与开发，不再是独立评测。

## 5. 三个数据集的职责

### 训练集

- 拟合模型参数
- 计算梯度
- 拟合均值、标准差、填充值和词表

### 验证集

- 选择超参数
- 比较模型版本
- 决定训练轮数与早停位置
- 调整特征和阈值

### 测试集

- 所有决策冻结后，估计最终泛化表现
- 不参与训练、调参、特征选择或阈值选择

如果反复根据测试结果修改模型，测试集就变成了验证集，需要新的独立测试数据。

## 6. 可复现的数据划分

```python
def split_indices(sample_count, train_ratio=0.7, valid_ratio=0.15, seed=42):
    rng = np.random.default_rng(seed)
    indices = rng.permutation(sample_count)

    train_end = int(sample_count * train_ratio)
    valid_end = train_end + int(sample_count * valid_ratio)

    return (
        indices[:train_end],
        indices[train_end:valid_end],
        indices[valid_end:],
    )
```

验证不重叠：

```python
assert set(train_indices).isdisjoint(valid_indices)
assert set(train_indices).isdisjoint(test_indices)
assert set(valid_indices).isdisjoint(test_indices)
```

分类数据不均衡时，应考虑分层划分，让各集合的类别比例接近。时间序列不能随机打乱，通常按时间顺序划分。

## 7. 预处理必须只拟合训练集

正确顺序：

```python
train_mean = x_train.mean(axis=0, keepdims=True)
train_std = x_train.std(axis=0, keepdims=True)
safe_std = np.where(train_std == 0, 1.0, train_std)

x_train_scaled = (x_train - train_mean) / safe_std
x_valid_scaled = (x_valid - train_mean) / safe_std
x_test_scaled = (x_test - train_mean) / safe_std
```

不能从完整数据计算：

- 均值和标准差
- 缺失值填充值
- 特征选择阈值
- 类别编码词表
- 文本 Tokenizer 词表
- 异常值边界

只要预处理“看到了”验证集或测试集的分布，就可能产生泄漏。

## 8. 基线模型

基线回答：如果不使用复杂模型，最简单方法能做到多好？

### 回归基线

始终预测训练集标签均值：

```python
baseline_value = y_train.mean()
valid_predictions = np.full_like(y_valid, baseline_value, dtype=np.float64)
```

### 分类基线

始终预测训练集中出现最多的类别：

```python
counts = np.bincount(y_train)
majority_class = np.argmax(counts)
```

也可以使用随机、规则或上一版本模型作为基线。新模型如果不能稳定超过合理基线，就没有证明其价值。

## 9. 损失函数与评价指标

损失函数用于训练优化，评价指标用于解释任务效果。两者可能相同，也可能不同。

| 任务 | 常见训练损失 | 常见评价指标 |
| --- | --- | --- |
| 回归 | MSE | MAE、RMSE、R² |
| 二分类 | 二元交叉熵 | 准确率、精确率、召回率、F1 |
| 多分类 | 交叉熵 | 准确率、宏平均 F1 |
| 语言模型 | Token 交叉熵 | 困惑度、任务评测 |

交叉熵可微且能利用概率置信度，适合梯度优化；准确率是离散指标，不适合直接作为梯度下降目标。

## 10. 回归指标

### MSE

```text
MSE = mean((y_pred-y_true)²)
```

### RMSE

```text
RMSE = sqrt(MSE)
```

RMSE 与目标变量单位相同，更容易解释。

### MAE

```text
MAE = mean(|y_pred-y_true|)
```

MAE 对大误差的惩罚没有 MSE 强，对异常值相对不敏感。

## 11. 混淆矩阵

二分类混淆矩阵：

| | 预测正类 | 预测负类 |
| --- | ---: | ---: |
| 真实正类 | TP | FN |
| 真实负类 | FP | TN |

- TP：真实为正，预测为正。
- TN：真实为负，预测为负。
- FP：真实为负，误报为正。
- FN：真实为正，漏报为负。

## 12. 准确率、精确率与召回率

```text
Accuracy  = (TP+TN) / (TP+TN+FP+FN)
Precision = TP / (TP+FP)
Recall    = TP / (TP+FN)
```

- 精确率关心：预测为正的样本中，有多少是真的正类？
- 召回率关心：所有真实正类中，有多少被找出来？

垃圾邮件过滤可能重视精确率，避免正常邮件被误删；疾病筛查可能重视召回率，避免漏掉患者。指标选择取决于错误成本。

类别极不平衡时，准确率可能误导。例如 1000 个样本中只有 10 个正类，全部预测负类也有 99% 准确率，但召回率是 0。

## 13. 欠拟合与过拟合

### 欠拟合

现象：训练集和验证集表现都差。

可能原因：

- 模型过于简单
- 特征不足
- 训练时间不足
- 学习率导致优化失败

### 过拟合

现象：训练集很好，验证集明显较差。

可能原因：

- 模型相对数据过于复杂
- 数据量少或噪声大
- 训练过久
- 数据分布差异

应同时看训练曲线和验证曲线：

```text
训练损失下降 + 验证损失下降：通常仍在有效学习
训练损失下降 + 验证损失上升：可能开始过拟合
二者都不下降：检查数据、梯度、学习率和实现
```

## 14. 优化与泛化

- 优化：在训练数据上找到较低损失参数。
- 泛化：在未见数据上保持良好表现。

训练损失下降只说明优化有进展。模型可能记住训练噪声，或者训练集与真实使用数据不一致。

改善泛化常用：

- 更多且更有代表性的数据
- 降低模型复杂度
- 正则化
- 早停
- 数据增强
- 更可靠的数据划分

## 15. 模型选择的正确协议

假设尝试三种学习率：

```text
0.001、0.01、0.1
```

正确做法：

1. 每个设置只在训练集拟合。
2. 在验证集比较表现。
3. 选择验证集最好的设置。
4. 冻结设置。
5. 最后在测试集评测一次。

不要选择测试集表现最好的模型后，再把同一个测试分数当最终无偏结果。

## 16. 实验记录

每次实验至少记录：

- 数据版本与划分随机种子
- 特征和预处理规则
- 模型版本
- 超参数
- 训练轮数
- 训练和验证指标
- 最终测试指标
- 运行时间
- 代码提交哈希
- 异常现象与结论

使用表格记录，避免凭记忆比较实验。

## 17. 排查模型不学习

建议顺序：

1. 检查 `X`、`y` 形状与对应关系。
2. 检查是否存在 `NaN`、`inf` 和异常尺度。
3. 检查损失与指标是否实现正确。
4. 使用很小数据集尝试过拟合。
5. 检查解析梯度与数值梯度。
6. 比较不同学习率。
7. 检查参数是否真的更新。
8. 与简单基线比较。

“让模型在 5～20 个样本上过拟合”是很有价值的测试：如果连小数据都记不住，通常是实现、优化或表达能力有问题。

## 18. 易错点

1. 没有明确任务就先选择模型。
2. 打乱 `X` 时没有同步打乱 `y`。
3. 用完整数据拟合预处理统计量。
4. 根据测试集反复调参。
5. 只报告模型指标，不比较基线。
6. 只看训练损失，不看验证表现。
7. 在类别不平衡任务中只看准确率。
8. 混淆参数与超参数。
9. 不固定随机种子，也不记录实验配置。
