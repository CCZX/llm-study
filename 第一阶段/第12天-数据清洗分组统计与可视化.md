## 3. 缺失值处理不是固定公式

先统计缺失：

```python
missing = evaluations.isna().agg(["sum", "mean"]).T
missing.columns = ["missing_count", "missing_rate"]
print(missing)
```

常见策略：

### 3.1 删除行

适合缺失比例很低、缺失原因近似随机且样本足够多的情况：

```python
without_missing_score = evaluations.dropna(subset=["score"])
```

### 3.2 使用固定值填充

适合缺失本身具有明确含义：

```python
df["notes"] = df["notes"].fillna("unknown")
```

不能随便使用 `0`。例如缺失的评测分数不等于得分为零。

### 3.3 使用组内统计量填充

练习数据中，可以用同一模型的平均分填充分数，用同一模型的显存中位数填充显存：

```python
score_fill = evaluations.groupby("model")["score"].transform("mean")
evaluations["score"] = evaluations["score"].fillna(score_fill)

memory_fill = evaluations.groupby("model")["gpu_memory_gb"].transform("median")
evaluations["gpu_memory_gb"] = evaluations["gpu_memory_gb"].fillna(memory_fill)
```

`transform` 返回与原 DataFrame 行数相同的 Series，因此可以与原列对齐。

填充会引入假设。报告中必须记录：填充了哪一列、使用什么规则、影响多少行。

## 4. 重复数据处理

检查完整重复：

```python
duplicates = evaluations.loc[evaluations.duplicated(keep=False)]
```

删除完整重复：

```python
evaluations = evaluations.drop_duplicates().copy()
```

业务键重复不一定是完整重复。评测表的 `run_id` 如果应当唯一，还要检查：

```python
duplicate_ids = evaluations.loc[
    evaluations.duplicated(subset=["run_id"], keep=False)
]
```

不要看到重复就删除：同一用户的两次访问、同一模型的两次独立实验可能都是合法记录。

## 5. 清洗后的验证

清洗不是执行完 `dropna` 就结束，必须验证不变量：

```python
assert evaluations["run_id"].is_unique
assert evaluations[["score", "gpu_memory_gb"]].notna().all().all()
assert evaluations["score"].between(0, 1).all()
assert (evaluations["latency_ms"] > 0).all()
```

还应比较清洗前后的行数，确认没有意外删除大量数据。

## 6. 分箱与类别列

把连续得分分成区间：

```python
evaluations["score_band"] = pd.cut(
```

## 7. groupby 与命名聚合

按模型汇总运行次数、平均分和平均延迟：

```python
summary = (
    evaluations.groupby("model", as_index=False)
    .agg(
        runs=("run_id", "count"),
        mean_score=("score", "mean"),
        mean_latency_ms=("latency_ms", "mean"),
    )
    .sort_values("mean_score", ascending=False)
)
```

命名聚合的好处是结果列名在代码中就已明确，不需要事后重命名。

按两个维度分组：

```python
model_task_summary = (
    evaluations.groupby(["model", "task"], as_index=False)
    .agg(mean_score=("score", "mean"))
)
```

## 8. merge 合并表格

将评测结果与模型参数量合并：

```python
merged = evaluations.merge(
    model_info,
    on="model",
    how="left",
    validate="many_to_one",
    indicator=True,
)
```

关键参数：

- `on`：关联键
- `how="left"`：保留左表全部评测记录
- `validate="many_to_one"`：验证评测表多行对应模型信息表一行
- `indicator=True`：增加 `_merge` 列，检查匹配情况

```python
print(merged["_merge"].value_counts())
```

如果右表的模型键重复，`many_to_one` 验证会报错，防止合并后行数意外膨胀。

## 9. pivot_table 透视表

比较不同模型在不同任务上的平均得分：

```python
pivot = evaluations.pivot_table(
    index="task",
    columns="model",
    values="score",
    aggfunc="mean",
)
```

透视表不会创造新信息，只是把长表转换成更适合横向比较的矩阵。

## 11. 相关系数的含义与局限

```python
correlation = evaluations[
    ["score", "latency_ms", "gpu_memory_gb"]
].corr()
```

Pearson 相关系数：

- 接近 `1`：强正线性关系
- 接近 `-1`：强负线性关系
- 接近 `0`：没有明显线性关系

局限：

- 相关不代表因果
- 对异常值敏感
- 接近零不等于完全没有关系，可能存在非线性关系
- 小样本相关系数非常不稳定
- 混杂变量可能同时影响两个指标

因此不要写“延迟导致得分提高”，只能写“在这份样本中，延迟与得分呈现某种相关关系”。

## 12. 为图表写结论

推荐使用三段式：

1. **观察**：图上直接看到什么。
2. **解释**：有哪些可能原因。
3. **限制**：这张图不能证明什么。

示例：

```text
观察：本样本中高延迟实验的得分整体较高。
解释：可能因为参数量更大的模型同时带来更高延迟和更高得分。
限制：样本量很小，且没有控制模型大小，不能证明增加延迟会提高得分。
```

## 13. 训练数据泄漏

数据泄漏是指训练过程中使用了预测时本不应知道的信息。

错误顺序：

```text
完整数据计算均值和标准差 → 标准化 → 划分训练/验证/测试集
```

这样训练数据间接使用了验证集和测试集的分布信息。

正确顺序：

```text
先划分数据
    ↓
只用训练集计算均值、标准差、填充值或类别词表
    ↓
用训练集统计量分别转换训练、验证和测试集
```

```python
train_mean = x_train.mean(axis=0, keepdims=True)
train_std = x_train.std(axis=0, keepdims=True)
safe_std = np.where(train_std == 0, 1.0, train_std)

x_train_scaled = (x_train - train_mean) / safe_std
x_valid_scaled = (x_valid - train_mean) / safe_std
x_test_scaled = (x_test - train_mean) / safe_std
```

同样规则适用于缺失值填充、特征选择、异常值阈值和词表构建。

## 14. 自测题

1. 为什么缺失分数不能直接填 `0`？
2. `groupby().agg()` 与 `groupby().transform()` 的结果形状有什么区别？
3. `merge(validate="many_to_one")` 能发现什么问题？
4. 散点图显示正相关，为什么不能直接得出因果结论？
5. 为什么标准化必须只使用训练集统计量？

参考答案：

1. 缺失代表未知，不代表真实得分为零。
2. `agg` 通常减少行数，`transform` 返回与原数据对齐的结果。
3. 能发现右表关联键不唯一导致的多对多合并风险。
4. 可能存在混杂变量、反向因果和小样本波动。
5. 防止验证集和测试集的分布信息泄漏到训练过程。

## 15. 易错点

1. 不保留原始数据，直接覆盖 CSV。
2. 没有业务依据就删除所有缺失行或统一填 `0`。
3. 删除“重复”前没有确认业务键和重复含义。
4. `groupby` 后忘记处理索引或命名结果列。
5. 合并表格时不检查行数变化和未匹配记录。
6. 图表没有标题、坐标名称或单位。
7. 把相关关系写成因果关系。
8. 在划分数据前计算标准化和填充统计量。
